CIT-147's first lesson (previous chapter) browsed one exported CI run as static
files. The first version of this lesson stepped through a fixed, twelve-item
array and called that "evaluation" -- it wasn't. Nothing was being checked
against anything; the array's own labels were just being displayed in order,
by two interchangeable data sources.

This version has exactly one axiom:

**`pkl/Ledger.pkl`'s `checkAccess(factID, vault)`** (open it in the editor to
the left) -- a worker fact's capability request is granted only if the
supervisor has recorded an approved grant for exactly this
`(factID, vault)` pair.

<CapabilityTraceViewer client:load />

**What's connected here, and how it's proven:**

- **The axiom** is shown above verbatim -- not summarized, not reworded --
  copied by `capability-spike/main.go`'s `loadApprovalCheck` straight out of
  `pkl/Ledger.pkl` at export time (`CapabilityTrace.checks[0]`).
- **The facts** it governs (`worker/flight_booking_area51.pkl` and a second,
  explicitly-rejected fixture) are listed as buttons; selecting one shows its
  current grant state and evidence.
- **The evaluation** shown per fact is not read from the trace file --
  it's computed live, in your browser, by
  [`ledgerCheckAccess.ts`](https://github.com/null-hype/null-hype.github.io/blob/main/tutorial-app/src/lib/ledgerCheckAccess.ts),
  a TypeScript replay of `checkAccess()`'s control flow, called fresh against
  whatever grant state the "Rewind"/"Advance" control has replayed up to.
  Advance past step 3 and watch the selected fact's verdict flip from
  `CAP_NO_GRANT` to clear the moment the supervisor's grant transition is
  folded into state -- that's the axiom reacting to a state change, not a
  new label being displayed.
- **The proof that the browser's replay is faithful**, not just plausible,
  is `ledgerCheckAccess.spec.ts` -- and it does not run only at build time.
  This lesson's `template: capability-check` boots a real Node WebContainer,
  `npm install`s a real `vitest`, and `npm test` runs that exact spec for
  real in the terminal panel below the file tree, against the exact same
  `evidence/capability-trace.json` this page reads. TutorialKit is running
  the test, not this component.

**Supporting files**, all real, all in the tree to the left: `pkl/Ledger.pkl`
(the axiom's source), `worker/flight_booking_area51.pkl` (the fact under
evaluation), and `evidence/capability-trace.json` (capability-spike's actual
`pkl test` run, captured once and committed as a fixture -- see
`capability-spike/main.go`'s `-trace-out` flag).
